# Multi-Site Compliance Onboarding Checklist

## 1. Purpose

This checklist defines the compliance steps required when onboarding a new site via the SIMBIOT wizard. It must be completed for every new site before the site goes live in SENTINEL. Completion generates a site-specific **Compliance Annex** (auto-generated by `create_site` API or manually from `site-compliance-annex-template.md`).

**Trigger:** SIMBIOT wizard discovers new building → complete this checklist before site goes live.
**Owner:** Compliance Lead + AI Engineering Lead.
**Deadline:** Before first shadow mode live transition.

---

## 2. Pre-Onboarding (Before SIMBIOT Installation)

### 2.1 Legal Entity Check

- [ ] Confirm data controller is **Asikhwele Building Projects (Pty) Ltd** (reg 2015/010878/07) for all new sites
- [ ] Verify any property management agreements cover BMS data processing under this entity
- [ ] If site is managed by a different entity (e.g., tenant-managed building), confirm POPIA data processing agreements are in place

### 2.2 Building Type Classification

Determine building type — this affects SANS 10400-X, Green Star eligibility, and LEU thresholds:

| Building Type | SANS 10400-X Zone Types | Green Star Eligible? | LEU Threshold Check? |
|--------------|------------------------|---------------------|---------------------|
| Commercial office | office_floor, meeting_room, lobby, server_room | Yes | Yes |
| Retail mall | retail_unit, common_area, plant_room | Yes (retail pathway) | Yes |
| Hotel | hotel_room, lobby, conference, pool, plant_room | Yes (hospitality pathway) | Yes |
| Warehouse | warehouse_zone, office_Mezzanine, plant_room | EDGE only | Yes |
| Industrial | factory_zone, office_Mezzanine, plant_room | EDGE only | Yes |
| Mixed-use | Combinations of above | Per GBCSA assessment | Yes |
| Residential (>4 units) | residential_unit, common_area, plant_room | Green Star Residential | Yes |

- [ ] Building type confirmed: `_______________`
- [ ] Green Star / EDGE eligibility confirmed: `_______________`
- [ ] GBCSA registered professional engaged (if Green Star): `Yes / No / N/A`

## 3. SIMBIOT Configuration (Day 1)

### 3.1 Site ID and Prefix

- [ ] Site ID assigned: `site-___` (format: `site-NNN`, zero-padded to 3 digits)
- [ ] Equipment prefix derived: `SNN`-derived from site ID (e.g., `site-003` → `S003`)
- [ ] Site ID registered in Supabase `buildings` table
- [ ] Site ID registered in `_registry.json`
- [ ] `shadow_mode_polling.py` verified as deriving prefix dynamically (no hardcoded S002)

**Equipment code pattern:** `{PREFIX}-{TYPE}-{ZONE}` (e.g., `S003-AHU-001`)

### 3.2 BMS Equipment Discovery

For each discovered equipment, record:

| Equipment | Code | BACnet/DALI/Modbus | Point Count | Safety-Critical? | Notes |
|-----------|------|-------------------|-------------|-----------------|-------|
| | | | | | Yes / No | |
| | | | | | Yes / No | |
| | | | | | Yes / No | |

**Safety-critical classification:**
- Chillers, boilers, heat pumps → Safety-critical (Tier 2 minimum)
- Fire dampers, smoke exhaust, emergency lighting → Life safety (no Tier 3 auto-execute)
- General AHUs, FCUs → Standard (Tier 3 eligible)

### 3.3 Site Bridge Configuration

- [ ] WireGuard VPN tunnel established (endpoint: `bms.sentinel-ai.co.za:51820`)
- [ ] MQTT over TLS credentials issued per site (`site_adapter_config` in Supabase)
- [ ] Site bridge subnet registered: `10.60.96.0/24` (site isolated)
- [ ] Cloudflare WAF geo-blocking configured (South Africa + operational countries only)
- [ ] Prometheus `site_id` label confirmed in DISCIPLINE_REGISTRY

## 4. Compliance Module Setup (Week 1)

### 4.1 Compliance Domain Eligibility

Not all compliance domains apply to all building types. Check applicable domains:

| Domain | Office | Retail | Hotel | Warehouse | Action Required |
|--------|--------|--------|-------|-----------|-----------------|
| OHS Act Checklist | ✅ | ✅ | ✅ | ✅ | Create zone checklist via API |
| Fire Safety (SANS 10400-T) | ✅ | ✅ | ✅ | ✅ | Add fire extinguisher inventory |
| Legionella Risk Management | ✅ | ✅ | ✅ | ⚠️ Only if cooling tower | Add cooling tower if present |
| Electrical CoC (SANS 10142-1) | ✅ | ✅ | ✅ | ✅ | Set 5-year renewal tracking |
| Lift Safety Inspections | ⚠️ If building has lifts | ⚠️ If building has lifts | ✅ | ❌ | Add lift inspection records if applicable |
| Emergency Lighting (IEC 62034) | ✅ | ✅ | ✅ | ✅ | Set daily auto-test schedule |
| Ventilation CO₂ (SANS 10400-X) | ✅ | ✅ | ✅ | ✅ | Zone CO₂ monitoring enabled |
| Indoor Air Quality | ✅ | ✅ | ✅ | ✅ | IAQ dashboard activated |

- [ ] Applicable compliance domains confirmed: `_______________`
- [ ] Compliance records created in Supabase for each applicable domain

### 4.2 Legionella Risk Assessment (If Cooling Tower Present)

- [ ] Cooling tower(s) identified during BMS discovery
- [ ] Cooling tower codes recorded in `legionella_risk_assessment` table
- [ ] Initial risk level set (default: `medium`)
- [ ] Water temperature monitoring wired to CO₂/temperature telemetry
- [ ] Treatment interval configured: 14d (high) / 30d (medium) / 60d (marginal) / 90d (low)

### 4.3 Electrical CoC Setup

- [ ] Electrical installation CoC obtained from certified electrician (SANS 10142-1)
- [ ] CoC recorded in `compliance_records` table with:
  - Certificate number
  - Certifying body name and registration number
  - Issue date
  - Expiry date (typically 5 years from issue)
  - Certificate type (new installation / alteration / SABS inspection / periodic)
- [ ] 30-day renewal alert set in compliance dashboard
- [ ] 90-day renewal alert set in compliance dashboard

### 4.4 Lift Safety (If Applicable)

- [ ] Lift register created: list all lifts by asset ID
- [ ] Inspection type set: 6-month periodic / annual insurance / post-repair
- [ ] Last inspection date recorded
- [ ] Next inspection date set and reminder scheduled
- [ ] Required tests documented: brake load test / speed governor test / emergency stop test

### 4.5 Emergency Lighting

- [ ] IEC 62034 test schedule set: daily auto-test at 03:00–03:30 SAST
- [ ] Battery health alert threshold set: <75% triggers alert
- [ ] 3-hour minimum runtime requirement confirmed
- [ ] 90-day battery health trend tracking enabled

## 5. SANS 10400-X Ventilation Setup (Week 1)

### 5.1 Zone Type Mapping

Unlike site-002 (which is office-only), multi-site buildings may have mixed zone types:

- [ ] Each BMS zone assigned a zone type from the SANS 10400-X zone type matrix:

| Zone Type | Min Outdoor Air Rate (L/s/m²) | CO₂ Advisory | CO₂ Alert | ACH Min |
|-----------|------------------------------|-------------|-----------|--------|
| office_floor | 1.0 | 800 ppm | 1000 ppm | 4 |
| meeting_room | 1.5 | 800 ppm | 1000 ppm | 6 |
| lobby | 1.5 | 900 ppm | 1100 ppm | 4 |
| server_room | 10.0 | 1000 ppm | 1200 ppm | 8 |
| plant_room | 5.0 | 1200 ppm | 1500 ppm | 5 |
| basement | 5.0 | 1000 ppm | 1500 ppm | 3 |
| retail_unit | 1.0 | 900 ppm | 1100 ppm | 4 |
| hotel_room | 1.0 | 800 ppm | 1000 ppm | 4 |
| pool_area | 5.0 | 900 ppm | 1100 ppm | 6 |
| warehouse_zone | 0.5 | 1000 ppm | 1500 ppm | 2 |

- [ ] Zone type map saved to `buildings/{site_id}/zone-type-map.json`
- [ ] Zone CO₂ monitoring enabled in `shadow_mode_polling.py` via `_sync_equipment_status()`
- [ ] `sentinel_ventilation_co2_ppm` Prometheus metric registered for new site
- [ ] Alert thresholds per zone type confirmed in Prometheus alerting rules

### 5.2 Outdoor Air Damper BACnet Points

- [ ] `OUTDOOR_AIR_DAMPER_PCT` point confirmed available from Desigo/Niagara
- [ ] Point registered in SIMBIOT point map
- [ ] `SentinelOutdoorAirDamperLow` alert configured in Prometheus (triggers at <10% with elevated CO₂)

## 6. Energy and LEU Determination (Week 1)

### 6.1 Energy Metering Setup

- [ ] Grid import meter confirmed: meter ID, meter type, location
- [ ] Solar generation metered (if applicable): inverter ID, capacity kW
- [ ] BESS metered (if applicable): capacity kWh, round-trip efficiency
- [ ] Sub-meters confirmed for HVAC, lighting, other (if available)
- [ ] Energy consumption data flowing to `energy_consumption_history` table

### 6.2 LEU Determination

- [ ] Building type and floor area confirmed
- [ ] Estimated monthly consumption calculated
- [ ] LEU threshold check: >400,000 kWh/month = LEU (report to DoE within 30 days)
- [ ] LEU status recorded: `Yes / No`
- [ ] If Yes: DoE registration initiated within 30 days of first consumption data

### 6.3 Green Star / EDGE (If Eligible)

- [ ] Green Star version confirmed: v2 (custom/rating) or EDGE
- [ ] Energy category credits mapped for this building type
- [ ] HVAC commissioning evidence scope defined
- [ ] SANS 961 energy model requirement confirmed (EDGE requires formal model)
- [ ] GBCSA registered professional appointed

## 10. Go-Live Criteria

The following must be verified before site transitions from shadow mode to live:

### 10.1 Compliance Checklist

- [ ] All applicable compliance domains in `compliance-module.md` have at least one record for this site
- [ ] Electrical CoC expiry date set and reminders active
- [ ] Legionella risk assessments created (if cooling tower present)
- [ ] Lift inspections scheduled (if applicable)
- [ ] Zone CO₂ monitoring active and data flowing
- [ ] Prometheus alerts verified firing for this site

### 10.2 Technical Checklist

- [ ] `shadow_mode_polling.py` — equipment codes derived from `site_id` (not hardcoded)
- [ ] `MultiSitePollingCoordinator` — new site picked up within 1 polling cycle
- [ ] Building JSON created at `buildings/{site_id}/building.json`
- [ ] Mode policy state file created at `buildings/{site_id}/{site_id}-mode-policy-state.json`
- [ ] Supabase `buildings` table record created
- [ ] `_registry.json` updated with new site ID
- [ ] Prometheus `sentinel_ml_hours_ingested{site_id="{site_id}"}` metric incrementing
- [ ] Telegram test alert sent successfully

### 10.3 Documentation Checklist

- [ ] Compliance Annex generated (via `create_site` API or from template)
- [ ] Compliance Annex filed in vault: `/home/bederf/sentinel-vault/sites/{site_id}/compliance/`
- [ ] Commissioning evidence collected in vault: `/home/bederf/sentinel-vault/sites/{site_id}/commissioning/`
- [ ] Site-specific equipment register filed in vault

## 11. Compliance Annex — Auto-Generation

The `create_site` API (`POST /api/sites`) auto-generates a compliance annex using `site-compliance-annex-template.md` as the template. The annex is saved to:

```
/home/bederf/sentinel-vault/sites/{site_id}/compliance/{site_id}-compliance-annex.md
```

**Manual generation:** Copy `site-compliance-annex-template.md` to the vault path above, fill in all `__PLACEHOLDER__` fields, and save.

**Annex contents:**
- Site identification (site ID, building type, address, legal entity)
- LEU determination (calculated from building type and sqm)
- Green Star/EDGE eligibility assessment
- SANS 10400-X zone type map for this site
- Equipment register with safety-critical classification
- Compliance domain status summary
- Regulatory obligations matrix
- Next review date
