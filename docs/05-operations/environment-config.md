# Production Environment Configuration

## systemd unit: sentinel-backend.service

`ENVIRONMENT=production` is set via:

- DropIn: `/etc/systemd/system/sentinel-backend.service.d/environment.conf`

The main unit file at `/etc/systemd/system/sentinel-backend.service` is left untouched. The DropIn approach means:

- The main unit can be regenerated by package updates without losing the override.
- `systemctl edit sentinel-backend` will continue to function as expected.
- Environment overrides stay out of git (no `.env` data in the repo or main unit).

## Verification

`systemctl show sentinel-backend | grep -i environment` must include `ENVIRONMENT=production` in the merged `Environment=` line, and the new file must appear in `DropInPaths`:

```
DropInPaths=.../sentinel-backend.service.d/environment.conf ...
```

## Reload (no restart required for verification)

```bash
sudo systemctl daemon-reload
sudo systemctl show sentinel-backend | grep -i environment
```

`daemon-reload` is required to pick up the new DropIn. The service itself is not restarted as part of this change — the running process already had `ENVIRONMENT=production` from `backend/.env`; the DropIn makes the value survive a git pull + main-unit rewrite.

## Why DropIn (not main unit)?

- The main unit lives in `/etc/systemd/system` and is not owned by this repo — we don't want to overwrite it on package updates.
- DropIns survive `systemctl edit` invocations and additional `*.conf` files in the same directory.
- Environment variables stay out of git (no `.env` data in main unit).

## Hardcoded secret note (Phase 226.1.6 audit)

The main unit currently contains hardcoded `Environment=` lines for `ELEVENLABS_API_KEY` and `ELEVENLABS_TTS_ENABLED`. A parallel phase (226.1.6 gitleaks audit) is reviewing this. Future hardening should move those values to an `EnvironmentFile=` (e.g. `/etc/sentinel/secrets.env`, mode 0600, owned by the service user) so secrets never appear in `/etc/systemd/system/*`.
